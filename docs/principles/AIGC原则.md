# AIGC 治理核心原则

> **用途**：所有 AIGC 相关 PR review 时的对照依据。
> **争议时拍板规则**：以下条款按顺序生效，前者优先于后者。
> **完整方案**见 [`../AIGC治理可执行方案_v1.1.md`](../AIGC治理可执行方案_v1.1.md)。

---

## 原则 1：医学准确性 > AI 味降低

> 宁可 AIGC 分高 10 分，不可让一个数字被改错。

**典型场景**：
- 改写器把"小鼠研究"改成"人体研究"以求自然 → **拒绝**
- 改写器为了降低重复用词，把"15%" 改成"15-20%" → **拒绝**
- 改写器丢失 `[文献1]` 标注 → **拒绝**

**这条原则压制其他所有指标**。当产品提出"AI 味分还是太高，能不能再激进点改写"时，先看是否会动事实——会，则拒绝。

---

## 原则 2：主战场在生成层，不是改写层

> 80% 的"反 AI"工作应该在 prompt 完成；改写只做兜底。

**典型场景**：
- 新增反 AI 规则时，**优先**写进 `_PARAGRAPH_RHYTHM_RULES` 让生成时遵守，而不是写进改写器
- 改写器需求暴增时，先反思：是不是 prompt 不够明确？
- 不要试图用改写救一篇生成阶段就跑偏的稿子

**反例**：
- ❌ "改写器应该自动给空洞段落补充具体数据" — 这会编造事实，违反原则 1
- ✅ "生成 prompt 要求每段必须包含至少 1 个数字或专有名词"

---

## 原则 3：改写绝不动事实

> 数字 / 文献号 / 药物名 / 剂量 / 适应症 / 结论方向 / 限定词强度 / 研究对象 全部锁定。

**改写器禁令清单**（实施于 `rewrite_to_reduce_ai` / `rewrite_multi_pass` system message）：

1. 禁止补充原文没有的具体数字、百分比、年份、人数
2. 禁止补充原文没有的药物名、机构名、研究名
3. 禁止改变研究对象（小鼠 vs 人体、儿童 vs 成人 等）
4. 禁止改变结论方向（"有效"不能改成"可能有效"或反之）
5. 禁止删除或重排 `[文献N]`、`[共识]`、`[推断:]`、`[[待补充:]]` 标注
6. 禁止改变限定词强度（"可能有效"→"有效"、"少数患者"→"部分患者"等）
7. 改写任务范围只是句式、节奏、连接词，不是补充信息

**自动校验**：`fact_guard` 模块用强 gate（study_subjects / citations / dosage）+ 弱 gate（数字归一化 / 药物候选）双层校验，强 gate 不通过直接回退。

---

## 原则 4：透明优于自动

> 让用户看到"哪段被改了、改了什么"，比追求自动黑盒更重要。

**典型场景**：
- 改写过的段落必须有 `[AI 优化]` 标记
- 用户可以查看每段 diff（改写前 vs 改写后）
- 用户可以单段恢复改写前内容
- 风险词命中必须对用户可见（顶部 alert / toast）

**反例**：
- ❌ "用户应该相信 AI 已经改对了，不用看改了什么" — 医学场景下，最终责任在用户，必须给用户审查机会
- ❌ "diff 视图增加复杂度，不做" — 机构客户的内容审核工作流就需要这个

---

## 原则 5：合规硬规则前置

> 法律红线（绝对化用语、处方药、剂量建议）必须事后正则硬过滤，不依赖 LLM 自觉。

**典型场景**：
- 不能依赖"prompt 里写了禁止治愈率 100%"就以为模型不会输出，必须有事后扫描
- "高风险决策建议"（具体剂量 / 手术方案 / 急救处置）→ **直接阻断**输出
- "绝对化用语"（治愈率 100% / 根治）→ 顶部 alert + 用户必须勾选确认

**红线词典治理**：必须由医学背景人（医生 / 药师）参与定义，不能只靠技术团队拍脑袋。短期参考国家卫健委、国家药监局公开的"医疗广告违规典型案例"。

---

## PR Review Checklist

提交涉及 AIGC 检测、生成层 prompt、改写器、风险词扫描的 PR 时，reviewer 必须勾选：

- [ ] 是否会动到医学事实（数字 / 药物 / 剂量 / 文献号 / 研究对象）？
- [ ] 改动是在生成层还是改写层？是否更适合放在生成层？
- [ ] 改写器改动有没有违反 7 条禁令？
- [ ] 用户可见性如何？改了什么用户能看到吗？
- [ ] 涉及合规规则的改动，是事前还是事后？是否依赖 LLM 自觉？

任何一项答案"不确定"或"否（且应该是）"的 PR，**block 直到澄清**。
